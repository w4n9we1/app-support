View Access Queries & Relationships on Your Phone

The queries saved inside an Access database and the relationships between its tables don't stay on the desktop. Open an MDB or ACCDB file on your phone and Database Viewer lists every saved query — with the SQL behind it rebuilt for reading — and draws the foreign-key relationships as a diagram. Everything runs on-device; the original file stays read-only.

What saved queries are

Access keeps a query's definition inside the database file itself — not in a separate document. When someone designs a query on the desktop, Access writes that definition into the file, right next to the tables it draws from. That is why a database can carry years of saved questions — customer lists, monthly totals, lookups across tables — and the definitions still travel with the file wherever it is copied. A query can read from plain tables or from other saved queries, and some databases stack them several layers deep. The MDB format guide covers where queries sit alongside tables, indexes and relationships.

View saved queries on your phone

Database Viewer lists the saved queries of an MDB or ACCDB file right on the phone. In the table structure screen, the Objects tab shows every query by name alongside the database's other objects — the MDB viewer guide describes the format itself, while this page stays with what is saved inside it. Tapping a query opens a read-only view: the definition is laid out in its parts, and the SQL behind it is rebuilt for reading. Queries that draw on other saved queries are expanded, so the whole chain is visible on one screen.

The rebuilt SQL is there for reading, not for running — the point is to see what each question asks, not to execute it. Nothing in this flow touches the original file.

Four steps take you from file to diagram:

  1. Open your database — tap Open file and pick your .mdb or .accdb. The health check inspects the file first and reports what it found before any table appears.
  2. Find the saved queries — open the table structure screen and switch to the Objects tab, where every query saved in the database is listed by name.
  3. Read a query and its SQL — tap a query to see its definition and the SQL rebuilt from it for reading; the query stays read-only on screen.
  4. See the relationships diagram — switch to the relationships view and the tables lay out as a diagram, with a line joining each pair of tables a foreign key connects.

See relationships as a diagram

Tables in a well-built database point at each other: an order carries the customer it belongs to, an order line carries the order it belongs to. Database Viewer turns those foreign keys into a picture — every table laid out as a box, a line drawn wherever one table references another — so the structure of the database reads at a glance. For Access files the diagram follows the relationships saved inside the database; for SQLite files it is drawn from the declared foreign keys, so the same view works across both — the SQLite viewer guide covers that format separately.

What you need

The database file itself — MDB or ACCDB for saved queries and relationships, or a SQLite file for the foreign-key diagram — and Database Viewer on an Android phone or an iPhone.

Frequently asked questions

Can I view Access queries on my phone?

Yes. Open an MDB or ACCDB file in Database Viewer on Android or iPhone and every query saved inside it is listed by name. Tapping a query shows its definition and the SQL rebuilt from it for reading — on-device, with no Microsoft Access involved.

What is a saved query?

A question about the data that Access stores inside the database file itself — for instance, which orders shipped late or which customers bought most. The definition, written in SQL (the language Access queries use), travels inside the file, so anything that reads the format can display it. Database Viewer shows the stored definition and rebuilds the SQL for reading.

Can I see table relationships?

Yes. Database Viewer draws the database's relationships as a diagram: every table appears as a box, and a line joins two boxes wherever a foreign key connects them. Access databases use the relationships saved in the file; SQLite databases are read through their declared foreign keys, so the same diagram works there too.

Do I need Microsoft Access?

No. The app carries its own native engine and reads MDB and ACCDB files directly on the phone — queries and relationships come straight out of the file. No copy of Access, no Windows machine and no converter website takes part.

Is the app free?

Free to start with a generous free preview — Pro is a one-time purchase. Opening a database, browsing its tables, reading its saved queries and its relationship diagram all work without paying. Pro — a single one-time purchase — adds export, editing and deeper analysis.

Is my database uploaded?

Never. Everything runs on the phone: the file is parsed by the app's own engine on-device, nothing is sent to a server, and no account exists. The original file opens read-only and is never modified.
