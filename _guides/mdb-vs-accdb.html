MDB vs ACCDB: What's the Difference?

MDB and ACCDB are two generations of the Microsoft Access database format: MDB is the Jet-engine default from Access 97 up to Access 2003, while ACCDB has served as the standard default from Access 2007 onward on the ACE engine, adding attachments, multi-value fields and stronger database encryption. Both open on a phone, no Microsoft Access needed.

What is the MDB format?

An MDB file is an Access database from the Jet generation — one file carrying the tables together with their saved queries, indexes and relationships. Access 97 shipped it on Jet 3.5, and Access 2000 to 2003 kept it on Jet 4.0, which is why documentation speaks of those two Jet versions. The format still turns up wherever legacy systems and archives live; the MDB viewer guide covers the format itself, and what is an MDB file explains it from the ground up.

What is the ACCDB format?

ACCDB is the generation Access 2007 made the new default, carried by the ACE engine that took Jet's place inside Access. What it adds shows up in daily work: attachment fields that store files inside a record, multi-value fields that keep a list of choices in one cell, calculated fields from Access 2010 onward, stronger database encryption, and tighter integration with SharePoint and Outlook. The ACCDB viewer guide walks through the format in detail.

Which one do you have?

Nine times out of ten the file extension settles it on sight: .mdb belongs to the older Jet generation, .accdb to databases created or re-saved from Access 2007 onward. That is all the identification most files ever need. The exception is a file that lost or swapped its extension in transit — and for that, Database Viewer runs a health check on every open: it inspects the bytes rather than the filename, reports what the database really is, and flags whether it reads cleanly before any table appears.

Can you convert MDB to ACCDB?

Yes, in one direction. From Access 2007 onward, open the MDB and choose Save As to write an ACCDB copy — tables, queries, forms and relationships come across. Treat the move as one-way: once the file is ACCDB, and especially once attachment or multi-value fields are in use, Access 2003 and older can no longer open it. If anyone on the team still runs an old version, keep the original MDB until every machine has moved. Converting also lifts no limits — both formats share the same 2 GB ceiling per database.

Frequently asked questions

Which is better, MDB or ACCDB?

Neither is universally better — it depends on where the database has to run. For a new database you design today, ACCDB is the format current Access saves by default, and it carries the newer field types and encryption. When a database must keep working with Access 2003 or older software that only understands Jet, staying with MDB preserves that compatibility. For simply reading the data, both behave the same in Database Viewer.

Can Access 2003 open ACCDB files?

No. ACCDB was introduced with Access 2007, and Access 2003 plus every earlier version cannot read it. The direction reverses from Access 2007 on: those versions open both ACCDB and MDB files. If someone is tied to an old copy of Access, keep the data in MDB format until their software is upgraded.

Are MDB and ACCDB files the same size limit?

Yes — both formats stop at 2 GB for a single database file. Because the ceiling belongs to the format itself, converting an MDB to ACCDB buys no extra room; a database outgrowing 2 GB has to be split or moved to a server-based backend, whichever extension it carries.

Can I convert MDB to ACCDB?

Yes. Access 2007 and later include a Save As path that writes an existing MDB database as an ACCDB copy. Treat it as a one-way upgrade: after converting — particularly once attachment or multi-value fields come into use — older versions of Access will not open the file, so keep the original MDB while any older software still needs it.
