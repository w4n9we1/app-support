What is actually inside a winmail.dat file?

A winmail.dat is not a single document — it is a transport container. When Outlook sends in Rich Text Format, it wraps the whole message into one TNEF package: the body in an RTF flavour, the header fields, and each attachment as its own encoded segment, sometimes with a calendar invite alongside. That is why the file looks like an unopenable blob on a phone: the mail app received a container it never had a reader for.

So “extracting the attachments” is really decoding the container and writing each segment back out as the file it was born as. Winmail Reader does that in a purpose-built decoder, on the device, without any Windows machine or Outlook licence in the loop.

How to extract attachments from winmail.dat on iPhone or iPad

  1. Install Winmail Reader from the App Store (iOS 17.0+ / iPadOS 17.0+). It is free to look inside.
  2. Open the winmail.dat file. In Mail, long-press the attachment and choose Save to Files, or tap Share and pick Winmail Reader. Files arriving through Files, iCloud Drive or another app work the same way.
  3. Read the attachment list. The app decodes the TNEF package on-device and shows each attachment with its file name and size, alongside the sender, subject and first screen of the message — no purchase needed to see what is inside.
  4. Extract the files. With Pro, tap an attachment to preview it, then extract that one file or all of them; extracted files can be saved to Files or shared with any app. The originals stay untouched, because extraction works from a copy.

The same route works for MSG and OFT files, EML, MHT, and for any message you open from inside an MBOX, PST, OST or OLM archive.

What you get back: original files, not conversions

Extraction writes out the attachments as they were sent — same names, same types, same bytes. A PDF invoice stays a PDF you can open anywhere; a Word document is not flattened into a picture or turned into another format; a photo keeps its original encoding. Nothing is re-rendered or re-compressed along the way.

From there, the extracted file can go straight into Files, into another app through the share sheet, or stay in the app while you work through the message. If what you actually need is the message as a fixed document rather than the attachments, the winmail.dat to PDF route is the other way round.

Online extractor or on-device app?

A web-based winmail.dat extractor has to receive the whole file before it can hand anything back. Mail attachments are where invoices, contracts and signed documents tend to live, so the upload is the part worth weighing. Both approaches return your files — the difference is where the container is opened.

Online extractor

The file leaves your device before you get any output. Processing happens on a third-party server, and its retention policy is outside your control.

Winmail Reader — on-device

Decoding, preview and extraction all run on your iPhone or iPad. Nothing is uploaded, no account is required, and the original file is opened read-only. Extracted files stay on the device until you share or delete them.

Frequently asked questions

Can I extract attachments from a winmail.dat file on iPhone?

Yes. Winmail Reader decodes the TNEF package on your iPhone or iPad, lists every attachment it carries and, with Pro, extracts them — one at a time or all at once. The extracted files are the originals as they were sent, so a PDF stays a PDF and a Word document stays a Word document. No Windows PC or Outlook is involved.

Is extracting attachments free?

No. Free to look inside: open the winmail.dat and see the sender, subject, first screen of the message and the attachment list with file names and sizes. Previewing and extracting the attachments is part of Pro — a single one-time purchase. An optional monthly subscription is also available, priced as shown in the app.

Which files can I pull attachments out of?

Any single message the app opens: winmail.dat (TNEF), MSG and OFT, EML, and MHT. Attachments inside messages in a mailbox archive — MBOX, PST, OST or OLM — are reached the same way once you open the message from the archive browser. XPS and OXPS documents are fixed-layout pages, so they carry no attachments.

Are the extracted attachments converted or renamed?

No. Attachments are written out as the original files with their own names and types, not re-rendered or converted. If a sender did send a converted copy from their side, that is what arrives — the app does not change the format on yours.

Are my files uploaded when attachments are extracted?

No. Decoding, previewing and extracting all run on your iPhone or iPad: no account and no uploads. Your original winmail.dat is opened read-only and extraction works from a copy, so the file you received is never modified. Extracted files stay on the device until you share them or delete them.

What if the attachment list looks incomplete or the file is damaged?

The file check-up runs before you extract anything: it reports what the file really is, how confident the detection is, and whether only part of the content could be decoded. If part of the message can be recovered, the app offers to show that recovered part. It does not repair a broken file — if an attachment was truncated in transit, the data is not there to recover.
