What is a SQLite file?

SQLite stores a relational database — tables, columns, primary and foreign keys — inside one ordinary file. There is no server behind it and nothing to install: the engine lives inside whatever application uses it, and the file itself is self-contained. Move that single file to another device or operating system and it opens there unchanged. The SQLite project calls it the most widely deployed database engine in the world, and the claim is easy to believe — it ships inside phone apps, browsers and operating systems alike.

The format never pinned down an official extension. Software that embeds SQLite saves the database as .sqlite, .sqlite3 or — more often than any of the “official” names — .db. All three refer to the same file format: a .sqlite3 and a .db written by SQLite differ in nothing but letters. That freedom is convenient for app developers and mildly confusing for everyone else, which the next section takes up.

Why is there a .db file on your device?

Because so many apps need structured local data, embedded databases are part of the plumbing of a modern phone. Chat histories, browser records, game saves and offline caches are commonly kept in SQLite databases, sitting in app folders where everyday use never notices them. They surface when a folder gets backed up, when files are copied over a cable, or when something a colleague shared lands in Downloads — and suddenly there is a .db on your screen with no explanation attached.

Before assuming what it holds, remember that .db is a generic extension rather than a certificate. SQLite databases use it, and so do files from other families — dBase tables, for one, carried .db for decades. Two identically named files can be entirely different formats. Database Viewer sidesteps the guessing: its health check examines the file’s contents, names the format it actually is, and only then decides how to read it.

Usually — SQLite inside

Apps that need structured local data lean on embedded SQLite databases — think chat histories, browser records or game saves. Their files appear as .db, .sqlite or .sqlite3, and all three open in Database Viewer through the same route.

SQLite is not the only database the app reads, either. Microsoft Access files — MDB from the Jet era and ACCDB from 2007 onward — go through the same on-device flow; the MDB guide and the ACCDB guide cover that side.

How to open a SQLite database on your phone

Four steps, one app, and the mystery file becomes readable data:

  1. Install Database Viewer — Android users find it on Google Play (it runs on 8.0 and newer) and iPhone users on the App Store, which asks for iOS 17.0 or later. Installing costs nothing, and so does opening databases.
  2. Open the file: tap Open file and point the picker at your .sqlite, .sqlite3 or .db. Android routes the pick through its Storage Access Framework chooser, reaching Downloads, Google Drive and the storage providers you already use; on iPhone you select the file in the Files app, where local folders, iCloud Drive and linked services sit side by side.
  3. Run the health check that greets the file before any data is shown. It reads the contents rather than trusting the name — decisive for a bare .db — and reports which format the file really is, whether the database is readable, which encoding the text uses and where damaged regions sit.
  4. Browse the database: open tables to read their rows, inspect the schema with column types, and follow the relationship diagram built from the file’s foreign keys. The SQL editor takes queries too, showing a free preview of the results; Pro unlocks the complete result set and export.

Run SQL queries on your phone

Frequently asked questions

What is a SQLite file?

A SQLite file is a relational database kept in a single file: its tables, columns and the links between them all live inside that one container. SQLite is described by its own project as the most widely deployed database engine, embedded in phone apps, browsers and operating systems. The format is self-contained and cross-platform — copy the file to another device and it opens there. The extensions .sqlite, .sqlite3 and .db all refer to this same format.

How do I view a SQLite database on Android or iPhone?

Install Database Viewer, tap Open file and pick the .sqlite, .sqlite3 or .db — on Android through the system picker, on iPhone through the Files app. A health check reads the file first and identifies the format from its contents; after that you browse tables, inspect the schema and can run SQL, all on the phone with nothing sent to a server.

Can I run SQL queries on my phone?

Yes. Database Viewer includes an SQL editor that runs your statements against the open database on the device itself, and the free tier lets you try queries with a free preview of the results. Pro — one purchase, yours for good — removes the preview limit and adds export of the data.

Is every .db file a SQLite database?

No. .db is a generic extension that several database families have used over the years — dBase tables carried it long before many SQLite apps did — so the name by itself cannot tell you what is inside. Database Viewer does not judge by extension: the health check examines the file’s contents and reports which format it really is before anything is displayed.

Is the app free?

Yes, with ads: the free tier covers opening files, the health report and browsing tables under a generous free preview. Pro arrives as a single one-time purchase: it switches the ads off and adds export, editing, file diff and more.

Is my database uploaded anywhere?

Never. Reading happens on your phone: the database and the queries you type are processed by the app itself, no server takes part at any point, and no account is needed. Query results and any exports stay on the device, saved only where you choose.
